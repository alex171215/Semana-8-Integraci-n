Paso 1

Levantar Kong en modo DB-less con Docker Compose

Crea una carpeta kong-gateway/ con este docker-compose.yml:

version: "3.8"
services:
  kong:
    image: kong:3.6
    environment:
      KONG_DATABASE: "off"
      KONG_DECLARATIVE_CONFIG: /kong/kong.yml
      KONG_PROXY_LISTEN: "0.0.0.0:8000"
      KONG_ADMIN_LISTEN: "0.0.0.0:8001"
    volumes:
      - ./kong.yml:/kong/kong.yml
    ports:
      - "8000:8000"
      - "8001:8001"

Y un kong.yml vacío por ahora:

_format_version: "3.0"
services: []
terminal
$ docker compose up -d
Verificación del Paso 1
  • docker compose up -d termina sin errores.
  • curl http://localhost:8001/status devuelve el estado de Kong.
Marca ambas casillas para continuar.
Paso 2

Definir el service y la route hacia tu API de Productos

Edita kong.yml:

_format_version: "3.0"
services:
  - name: productos-service
    url: http://host.docker.internal:3000
    routes:
      - name: productos-route
        paths: ["/productos"]

Piensa

host.docker.internal permite que el contenedor de Kong alcance servicios corriendo en tu máquina host, fuera de Docker. Si usas Linux sin Docker Desktop, puede que necesites la IP real del host.

terminal
$ docker compose restart kong
Verificación del Paso 2
  • docker compose restart kong no reporta errores.
  • Puedo explicar la diferencia entre el campo url del service y paths de la route.
Marca ambas casillas para continuar.
Paso 3

Probar que Kong reenvía correctamente (Proxy simple)

Compara la respuesta directa contra la respuesta a través de Kong:

terminal
$ curl http://localhost:3000/productos
$ curl http://localhost:8000/productos
Verificación del Paso 3
  • curl http://localhost:8000/productos (vía Kong) devuelve el mismo JSON que el puerto 3000 directo.
Marca la casilla para continuar.
Paso 4 — El corazón de la semana

Aplicar el plugin rate-limiting

Agrega el plugin en kong.yml:

_format_version: "3.0"
services:
  - name: productos-service
    url: http://host.docker.internal:3000
    routes:
      - name: productos-route
        paths: ["/productos"]
    plugins:
      - name: rate-limiting
        config:
          minute: 5
          policy: local
terminal
$ docker compose restart kong
$ for i in 1 2 3 4 5 6; do curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/productos; done
Verificación del Paso 4
  • Las primeras 5 peticiones devuelven 200.
  • La 6ª petición (mismo minuto) devuelve 429 Too Many Requests.
No sigas sin haber visto el 429 real.
Paso 5

Propagar un encabezado de trazabilidad (X-Correlation-Id)

Agrega el plugin request-transformer:

    plugins:
      - name: rate-limiting
        config:
          minute: 5
          policy: local
      - name: request-transformer
        config:
          add:
            headers: ["X-Correlation-Id:kong-generado"]

Reinicia Kong, envía una petición y agrega un log temporal en nestjs-productos-api que imprima req.headers['x-correlation-id'].

terminal
$ docker compose restart kong
$ curl -v http://localhost:8000/productos
Verificación del Paso 5
  • Confirmé en la consola de nestjs-productos-api que el header X-Correlation-Id llegó, inyectado por Kong.
Marca la casilla para continuar.
Paso 6

Cierre parcial: comparar con y sin Gateway

Detén temporalmente Kong y confirma que nestjs-productos-api sigue respondiendo directo en el puerto 3000, pero el 8000 ya no responde.

terminal
$ docker compose stop kong
$ curl http://localhost:3000/productos
$ curl http://localhost:8000/productos
$ docker compose start kong

Punto único de fallo

Confirmaste en carne propia que Kong es, por diseño, un punto único de fallo para el tráfico externo — exactamente lo que advierte la teoría (§8.5).

Verificación del Paso 6
  • Confirmé que sin Kong el puerto 8000 no responde pero el 3000 sí.
Marca la casilla para continuar.
Paso 7 — Reto

Patrón Aggregator/BFF: combinar REST + GraphQL

Crea un proyecto nuevo nestjs-bff-productos con un endpoint que combine tu API REST y tu API GraphQL:

@Get('productos-completos/:id')
async obtenerCompleto(@Param('id') id: string) {
  const rest$ = this.http.get(`http://localhost:3000/productos/${id}`);
  const restRes = await firstValueFrom(rest$);
  // Si tienes la API GraphQL disponible, agrega aqui una segunda llamada
  // y combina ambos resultados.
  return { ...restRes.data, fuente: 'aggregator' };
}

Agrega la ruta adicional en kong.yml:

  - name: bff-productos-service
    url: http://host.docker.internal:3001
    routes:
      - name: bff-productos-route
        paths: ["/productos-completos"]
terminal
$ nest new nestjs-bff-productos
Verificación del Paso 7
  • curl http://localhost:8000/productos-completos/1 devuelve una respuesta combinada.
  • Puedo explicar por qué esto es un Aggregator y no un Proxy simple.
Marca ambas casillas para continuar.
